# הקמה ב-Render (צעד אחר צעד)

כל מה שבקוד כבר מוכן: `render.yaml` מגדיר שירות web, ארבע משימות cron, Postgres ו-IB Gateway פרטי. אין מפתחות בקוד; כולם נכנסים בלוח של Render, ולא בצ'אט.

## מה צריך לפני

1. **בוט טלגרם:** ב-BotFather שולחים `/newbot`, מקבלים טוקן. שולחים לבוט החדש הודעה כלשהי, ואז פותחים
   `https://api.telegram.org/bot<הטוקן>/getUpdates` ומעתיקים את `chat.id` (זה ה-chat id שלך).
2. **מפתח Anthropic API** מ-console.anthropic.com (חיוב נפרד ממנוי Claude). תקרה חודשית: 150$ (הוגדרה גם בקוד: 10$ ליום).
3. **מפתח FRED** (חינם) ו-**FMP** (גיבוי למחירים). אין עדיין מפתח (FMP, FRED, או Anthropic)? משאירים את השדה ריק, לא `none`: בלי `ANTHROPIC_API_KEY` הריצות רצות בלי ה-Agents, ובלי FRED בלי נתוני המקרו. מוסיפים אחר כך ב-Environment של qt-web ועושים Manual Sync.
4. **סיסמה ללוח הבקרה** (משמשת גם לחתימת קישורי "פרטים"). ממציאים אחת חזקה.
5. **משתמש API ב-IBKR** (פירוט בסעיף IBKR למטה): שם משתמש וסיסמה של חשבון ה-paper.

## ההקמה

1. ב-Render: New → Blueprint → בוחרים את הריפו `trading-system-v2`. Render קורא את `render.yaml`.
2. Render מבקש את הערכים שמסומנים `sync: false`, **פעם אחת בלבד**:
   - ב-`qt-web`: `ANTHROPIC_API_KEY`, `FRED_API_KEY`, `FMP_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `DASHBOARD_PASSWORD`.
     ארבע משימות ה-cron מעתיקות אותם מ-`qt-web` לבד.
   - ב-`qt-ibgateway`: `TWS_USERID`, `TWS_PASSWORD`.
   `TELEGRAM_WEBHOOK_SECRET` נוצר לבד, והכתובת הציבורית של `qt-web` עוברת ל-cron לבד.
3. אחרי שה-web עלה: Shell של `qt-web` → `qt set-webhook`. מעכשיו הכפתורים בטלגרם עובדים.
4. שולחים לבוט את קובץ התיק `portfolio.yaml` (מבנה כמו `examples/portfolio.yaml`). הבוט עונה "התיק עודכן".
5. בדיקה: Shell → `qt run daily --as-of <יום מסחר אחרון>`. אמורה להגיע הודעת סיכום ופריטים עם כפתורים.
6. לוח הבקרה: הכתובת של `qt-web`, משתמש כלשהו + הסיסמה.

**החלפת מפתח בהמשך:** משנים אותו ב-`qt-web` (Environment), ואז בדף ה-Blueprint לוחצים Manual Sync כדי שה-cron יקבלו את הערך החדש.

## IBKR: IB Gateway קבוע

`qt-ibgateway` מריץ את IB Gateway בלי מסך (התמונה `gnzsnz/ib-gateway`, שכוללת IBC להתחברות אוטומטית), כשירות פרטי:
רק השירותים שלנו מגיעים אליו, בכתובת `IBKR_HOST:4004`. הוא דולק כל הזמן, ומתאתחל לבד כל לילה ב-23:45 ניו יורק בלי לבקש 2FA.

**לפני ההקמה, ב-IBKR:**
1. **משתמש נפרד ל-API.** ל-IBKR יש סשן אחד לכל משתמש: אם תתחבר ל-TWS או לאפליקציה עם אותו משתמש, ה-Gateway ינותק.
   ב-Client Portal: Settings → Users & Access Rights → מוסיפים משתמש (למשל `ilay-api`). אם קשה לקבל למשתמש הזה גישת paper,
   אפשר להשתמש במשתמש ה-paper הקיים, ופשוט לא להתחבר איתו ל-TWS או לאפליקציה.
2. **חשבון paper:** Settings → Paper Trading Account. מכניסים ל-Render את שם המשתמש והסיסמה **של ה-paper** של משתמש ה-API.
3. **נתוני שוק ל-paper:** אם צריך נתונים בזמן אמת דרך ה-API, מפעילים "Share real-time market data subscriptions with paper account"
   ומוודאים שלמשתמש ה-API יש את המנויים. לנרות יומיים ולשרשרת אופציות בגרסה 1 נבדוק בהפעלה הראשונה מה בדיוק נדרש.

**מצב בגרסה 1:** paper בלבד, ו-`READ_ONLY_API=yes`, כלומר ה-API לא יכול לשלוח פקודות. פקודות ב-paper, ובהמשך חשבון אמיתי,
הן החלטה נפרדת (שלב 9 בארכיטקטורה). חשבון אמיתי ידרוש אישור 2FA בטלפון בערך פעם בשבוע, ואחרי כל הפעלה מחדש של השירות.

**כללים לשירות הזה:**
- הגרסה של התמונה נעולה ב-`render.yaml`. מעדכנים אותה רק בכוונה, בסוף שבוע.
- לא לעשות Restart/Redeploy ל-`qt-ibgateway` בזמן המסחר. בחשבון אמיתי כל הפעלה מחדש מבקשת 2FA.
- הלוג של השירות ב-Render מראה אם ההתחברות הצליחה (`Login has completed`).

**סיכון ידוע:** פרויקט IBC (ההתחברות האוטומטית) הוכרז כ"פרויקט שפרש" ב-1.9.2026. התמונה עדיין כוללת אותו ומתעדכנת,
אבל אם IBKR ישנו את מסך ההתחברות, זה יכול להישבר. החלופה לטווח ארוך: ה-Web API של IBKR, בלי Gateway.

## כל חודש

הריצה החודשית (שבת בשבוע השני) מחכה לקובץ המקרו הידני (ISM PMI/NMI, NFIB) בפורמט YAML:
`ism_pmi: {'2026-09': 49.1, ...}`. הבוט מזכיר; שולחים לו את הקובץ והריצה ממשיכה לבד.

אפשר להוסיף לאותו קובץ את טבלת התעשיות מדוח ה-ISM (S05-R6, S05-R9). זה לא חובה, אבל בלי זה ההכנה החודשית מדלגת על הטבלה:
```yaml
ism_growing: {'2026-09': [Machinery, Chemical Products]}      # בסדר של הדוח
ism_contracting: {'2026-09': [Textiles, Paper Products]}
ism_short_supply: {'2026-09': {Copper: 4, Electronic Components: 2}}   # מספר החודשים ברצף, כמו בדוח
```

NAAIM (S09-R33) עבר למנויים באוגוסט 2026, ולכן גם הוא מגיע מהקובץ הידני: הערכים השבועיים מהחודש האחרון, `naaim: {'2026-09-30': 72.5, ...}`.
עם שנה של ערכים ההכנה החודשית מחשבת גם קיצון (ממוצע ± סטיית תקן, D-S09-8). את ה-COT היא מושכת לבד מה-CFTC.

תקרות החשיפה (D-S11-7) נכתבות בקובץ התיק, כחלק מההון: `caps: {long_max: 1.0, short_max: 0.3, net_max: 0.9}`.
הריצה היומית מסמנת חריגה, וההכנה החודשית מציגה את החשיפה מול התקרות. בלי תקרות היא מזכירה שצריך לקבוע אותן.

## עלות צפויה

web starter 7$ · Postgres basic-256mb כ-6$ · ארבע משימות cron לפי דקות ריצה (מעט דולרים; השבועית על standard כי המחקר צריך זיכרון) · IB Gateway על standard (2GB, דולק כל הזמן) כ-25$ · בסה"כ כ-45–50$ לחודש. לאמת במחירון של Render.
סוכנים: עד 10$ ליום בריצות היומיות, ועד 25$ למחקר השבועי (models.yaml), בתוך התקרה החודשית של 150$.
